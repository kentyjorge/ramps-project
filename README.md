# Ramps - Revenue Connect Integration

This project calls Revenue Connect REST APIs from Apex using a self-referencing Named Credential.

> **Target org:** an existing **sandbox / Developer Edition / dev** org with
> Revenue Cloud (RLM) enabled. **Never deploy to production** from this flow.
>
> Prior deployment logs and change history have moved to
> [`SESSION-HISTORY.md`](./SESSION-HISTORY.md) to keep this README focused on
> setup and deploy.

## What's included

- **Apex:** `RevConnectCallout` (Revenue Connect callout via Named Credential),
  `QuoteRampController` (ramp orchestration) + tests
- **LWC:** `quoteRampBuilder` (the ramp UI)
- **Flow:** `Launch_Create_Ramps` (screen-flow wrapper)
- **Quick Action:** `Quote.Ramp_Lines`

Deploy mechanism: **source-format SFDX project** (`sf project deploy start`) **plus
a one-time manual org setup** (Connected App / Auth Provider / External + Named
Credential) that no deploy can perform for you.

## Org Setup: Named Credential, Auth Provider, Connected App

The Apex callout uses a self-referencing Named Credential (`SelfOrgNC`) so Salesforce can call back into its own Revenue Cloud Connect REST API on behalf of the running user. The following must be configured in every target org before the ramp builder will work.

---

### Step 1 — Create the Connected App (`RevCloud`)

**Setup → App Manager → New Connected App**

| Field | Value |
|---|---|
| Connected App Name | `RevCloud` |
| API Name | `RevCloud` |
| Contact Email | your admin email |
| Enable OAuth Settings | checked |
| Callback URL | `https://<your-org>.my.salesforce.com/services/authcallback/RevCloud` (update after Auth Provider is created) |
| Selected OAuth Scopes | `Access and manage your data (api)`, `Perform requests on your behalf at any time (refresh_token, offline_access)` |
| Require Secret for Web Server Flow | checked |
| Require Secret for Refresh Token Flow | checked |

Save. Note the **Consumer Key** and **Consumer Secret** — needed in Step 2.

> **After completing Step 2**, come back and update the Callback URL in this Connected App to the one generated by the Auth Provider (it will look like `https://<your-org>.my.salesforce.com/services/authcallback/RevCloud`).

---

### Step 2 — Create the Auth Provider (`RevCloud`)

**Setup → Auth. Providers → New**

| Field | Value |
|---|---|
| Provider Type | Salesforce |
| Name | `RevCloud` |
| URL Suffix | `RevCloud` |
| Consumer Key | (from Connected App) |
| Consumer Secret | (from Connected App) |
| Authorize Endpoint URL | `https://<your-org>.my.salesforce.com/services/oauth2/authorize` |
| Token Endpoint URL | `https://<your-org>.my.salesforce.com/services/oauth2/token` |
| Default Scopes | `api refresh_token offline_access` |

Save. Copy the **Callback URL** shown at the bottom of the saved Auth Provider record and paste it into the Connected App's Callback URL field (Step 1).

---

### Step 3 — Create the External Credential (`SelfOrgOAuthEC`)

**Setup → Named Credentials → External Credentials tab → New**

| Field | Value |
|---|---|
| Label | `SelfOrgOAuthEC` |
| Name | `SelfOrgOAuthEC` |
| Authentication Protocol | OAuth 2.0 |
| Auth Provider | `RevCloud` |

Save, then add a Principal:

**Principals section → New**

| Field | Value |
|---|---|
| Parameter Name | `default` |
| Identity Type | Named Principal |
| Authentication Status | (will show as Not Authenticated until Step 5) |

Save.

---

### Step 4 — Create the Named Credential (`SelfOrgNC`)

**Setup → Named Credentials → Named Credentials tab → New**

| Field | Value |
|---|---|
| Label | `SelfOrgNC` |
| Name | `SelfOrgNC` |
| URL | `https://<your-org>.my.salesforce.com` (org instance URL, no trailing slash) |
| External Credential | `SelfOrgOAuthEC` |
| Allow Formulas in HTTP Header | checked |
| Allow Formulas in HTTP Body | checked |

Save.

---

### Step 5 — Authorize the Principal

**Setup → Named Credentials → External Credentials → SelfOrgOAuthEC → Principals → default → Authenticate**

This redirects through the Salesforce OAuth flow. Log in as the user whose session the callout will run under (typically the admin or an integration user). On success the principal status changes to **Authenticated**.

---

### Step 6 — Grant Permission Set Access

Users who will trigger the ramp builder need access to the External Credential principal. Add this to the relevant permission set:

**Permission Set → External Credential Principal Access → Edit → add `SelfOrgOAuthEC - default`**

---

### Quick verification

After setup, confirm the Named Credential resolves correctly by running this in **Execute Anonymous**:

```apex
HttpRequest req = new HttpRequest();
req.setEndpoint('callout:SelfOrgNC/services/data/v65.0/limits');
req.setMethod('GET');
HttpResponse res = new Http().send(req);
System.debug(res.getStatusCode() + ' ' + res.getBody().left(200));
```

A `200` response confirms the credential is wired up correctly. A `401` means the principal is not authenticated (repeat Step 5). A `403` means the permission set access is missing (Step 6).

## Apex Callout Pattern

- Auth: handled by Named Credential (no manual `Authorization` header in Apex)

## Use Case: Quote-Level Group Ramp Builder

The Ramp Builder allows sales reps to split a Quote into multiple time-based segments (ramp periods). Each segment is a `QuoteLineGroup` with `IsRamped = true`, distinct start/end dates, and optional uplift/discount.

### Flow Summary

1. **Group all lines** into segment 1 (Revenue Connect `place` API)
2. **Configure segment 1** as ramped with dates and segment type (`EditGroup` action)
3. **Ungroup one-time lines** from the ramped group (Revenue Connect `place` API — sets `QuoteLineGroupId` to null)
4. **Clone** segment 1 to create segments 2…N (Revenue Connect `clone` API)
5. **Align dates** on all ramped groups (`EditRampSchedule` action)
6. **Re-add one-time lines** back to segment 1 (Revenue Connect `place` API)
7. **AddProducts** — duplicate selected subscription lines into segments 2+
8. **Apply uplift/discount** per-segment to non-one-time lines
9. **Propagate SegmentType** from groups to line items
10. **Update Quote dates** — aggregate start/end/term from all segments

### One-Time Line Handling

One-time products (e.g., implementation fees) should only appear in segment 1. They must be excluded from the clone operation so they don't get duplicated into every segment.

**Key constraint:** Revenue Connect API calls execute in their own HTTP transactions, separate from the calling Apex transaction. DML changes made in Apex are not committed (and therefore not visible to Revenue Connect) until the entire Apex method finishes.

This means the ungroup/regroup of one-time lines **must** be done via Revenue Connect calls — not DML — so the committed state is visible to subsequent clone operations.

---

## Architecture: Revenue Connect Transaction Isolation

Each Revenue Connect API call commits in its own database transaction:

```
Apex transaction (applyGroupRamp):
  ├─ RC call → groups all lines into segment 1 (commits ✓)
  ├─ RC call → edits group as ramped (commits ✓)
  ├─ RC call → ungroups one-time lines (commits ✓, visible to next call)
  ├─ RC call → clone (reads DB — one-time lines NOT in group ✓)
  ├─ RC call → align dates (commits ✓)
  ├─ RC call → regroups one-time lines back to segment 1 (commits ✓)
  ├─ RC call → AddProducts into segments 2+ (commits ✓)
  ├─ RC call → apply uplift/discount (commits ✓)
  ├─ RC call → propagate SegmentType (commits ✓)
  └─ DML → update Quote dates (commits when Apex tx finishes)
```

### Why DML Doesn't Work for Ungroup/Regroup

```
Apex transaction:
  ├─ DML: update oneTimeLines (QuoteLineGroupId = null) — UNCOMMITTED
  ├─ RC call: clone — reads committed DB state — one-time lines STILL in group ✗
  └─ ... DML only commits after entire Apex method returns
```

Revenue Connect cannot see uncommitted DML changes from the calling Apex transaction. The fix uses Revenue Connect's own `place` API (with `"QuoteLineGroupId": null` in the payload) to ungroup lines, ensuring the change is committed and visible before the clone step executes.

## Key Payload Patterns

### Ungroup Lines (set QuoteLineGroupId to null)

```json
{
  "pricingPref": "Skip",
  "catalogRatesPref": "Skip",
  "configurationPref": { "configurationMethod": "Skip", ... },
  "graph": {
    "graphId": "ungroupOneTime",
    "records": [
      { "referenceId": "<quoteId>", "record": { "attributes": { "type": "Quote", "method": "PATCH", "id": "<quoteId>" } } },
      { "referenceId": "<lineId>", "record": { "attributes": { "type": "QuoteLineItem", "method": "PATCH", "id": "<lineId>" }, "QuoteLineGroupId": null } }
    ]
  }
}
```

Note: `"QuoteLineGroupId": null` is JSON null (no quotes). `pricingPref: "Skip"` avoids repricing during the temporary ungroup.

### Group Lines (assign to a QuoteLineGroup)

```json
{
  "pricingPref": "System",
  "catalogRatesPref": "Skip",
  "configurationPref": { "configurationMethod": "Skip", ... },
  "graph": {
    "graphId": "groupQuoteLines",
    "records": [
      { "referenceId": "<quoteId>", "record": { "attributes": { "type": "Quote", "method": "PATCH", "id": "<quoteId>" } } },
      { "referenceId": "<lineId>", "record": { "attributes": { "type": "QuoteLineItem", "method": "PATCH", "id": "<lineId>" }, "QuoteLineGroupId": "<groupId>" } }
    ]
  }
}
```

### Clone a Ramped Group

```json
{
  "recordIds": ["<groupId>"],
  "salesTransactionId": "<quoteId>",
  "options": { "lineScope": "AllLines" }
}
```

## Post-deploy steps

1. Complete the org setup steps above if you haven't (the deploy does not create the credentials).
2. **Add the `Ramp Lines` quick action** to the Quote page layout: Setup → Object
   Manager → Quote → Page Layouts → *Mobile & Lightning Actions* → drag **Ramp
   Lines** → Save.
3. Confirm the `Launch_Create_Ramps` flow is active (Setup → Flows).

## Verify

Open/create a Quote with ≥2 subscription products and ≥1 one-time product → **Ramp
Lines** → configure 2 segments (e.g. Y1: 12 mo, 0% uplift; Y2: 12 mo, 10% uplift)
→ select subscription products to duplicate → **Apply Ramp**. Expect: 2
`QuoteLineGroup`s (`IsRamped = true`), subscription lines in both, one-time lines
only in segment 1.

## Safety

- Metadata-only deploy — no data is loaded or deleted by the deploy.
- The ramp builder **modifies Quote line groups and pricing** when run; exercise
  it on test quotes first.

## Troubleshooting

- `401/403`: verify External Credential principal authorization and user access.
- `404`: verify Revenue Connect route/version availability for your org, for example:
  - `/services/data/v66.0/connect/`
  - `/services/data/v66.0/connect/rev/`
- `400` on clone: one-time lines may still be in the ramped group. Confirm the ungroup step uses Revenue Connect (not DML) so the change is committed before clone.
- Clone returns "isn't the primary segment": fallback logic attempts line-level clone instead of group-level clone.
